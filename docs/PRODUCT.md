# Shooters Tools — бізнес- і технічний опис продукту

**Shooters Tools** — портал на **[shooters-tools.com](https://shooters-tools.com)**: один **SPA** (**Vercel**), локалізація **`/:locale`** (`uk` / `en`), спільний **PortalShell**. У межах того ж деплою працюють **декілька модулів** з різним призначенням: довідники й утиліти для стрілецького практикингу, **акаунт** (Supabase Auth), модуль **«Матчі»** (каталог, реєстрація, кабінет організатора, експорт у PractiScore), а також **Stage Builder** (**`/:locale/stage-builder`** у тій самій оболонці) з окремою віссю share-маршрутів **`/v/*`**, **`/e/*`**.

Цей файл дає **загальну картину продукту** (навіщо сайт людині й як зібраний технічно). Детально лише редактор — [FUNCTIONALITY.md](./FUNCTIONALITY.md); інженерія, env, PSC API — [TECH.md](./TECH.md); дорожня карта порталу — [PORTAL_PLAN.md](./PORTAL_PLAN.md); задачі між розділами — **[PLANNING_INDEX.md](./PLANNING_INDEX.md)**. Продуктові етапи **V0/V1/V2** у [VERSIONING.md](./VERSIONING.md) переважно описують **еволюцію редактора**; поруч існують окремі плани модулів порталу й **MA‑*** для матчів.

**Повний знімок репозиторію** — [PROJECT_CONTEXT.md](./PROJECT_CONTEXT.md).

## Частина A. Бізнес-опис

### A.1. Позиціонування порталу

Портал **не зводиться до редактора**: користувач може заходити за **іншими сценаріями** — калькулятор, довідник правил, **оголошення та реєстрація на матчі**, робота з профілем без відкриття Stage Builder.

Нижче — склад продукту в одній таблиці (бізнес-сенс модулів; техніка — частина **B**).

| Модуль | Для кого | Яку задачу закриває |
|--------|----------|---------------------|
| **Stage Builder** | орг.-спорт інфра, RO, тренери | спроєктувати вправу в метрах, 3D, брифінг, PDF, файл `*.stage.json`; PWA |
| **Поділитися вправою (share)** | ті самі + стрілки | опублікований перегляд **`/v/...`** / редактор за посиланням **`/e/...`**; основа зв’язку **матча з вправами** |
| **Матчі** (за **`VITE_ENABLE_MATCH_PORTAL`**) | організатори, стрілки | календар/каталог, картка події, заявки, скводи, ростер, **`.psc`** для PractiScore; модерація організаторів |
| **RO Helper** | RO, спортсмени | структуровані правила / процедури (контент), швидкий пошук під змаганням |
| **Hit Factor** | стрілки | розрахунок на змаганні / тренуванні |
| **Акаунт (`/account`)** | користувач порталу | вхід email, профіль учасника, заявка на роль організатора матчів |
| **Політика публікації** | автори share | текст згоди перед публікацією вправи |

Сервіс **не** замінює офіційні регламенти **IPSC**, рішення **RM** та сертифікований софт змагань — він **зменшує тертя** між проєктуванням, комунікацією й побутовими задачами на змаганні.

### A.2. Stage Builder (редактор вправ) — у фокусі як «важкий» модуль

**Stage Builder** — безкоштовний веб-редактор **стрільбищних вправ у стилі IPSC**: мішені й реквізит на **метричному плані**, **3D** (увімкнювані «плоскі» тіні та Ч/З для знімка в PDF), **брифінг** із опційними логотипами ФПСУ/IPSC та назвою матчу, **PDF** зі знімком і **QR**. Вправи зберігаються в **акаунті** («Мої вправи») або у файлі `*.stage.json`. Доступ **`/:locale/stage-builder`**; двомовність **UK/EN**; офлайн після установки як **PWA**.

### A.3. Цільова аудиторія за контекстом

**Планування майданчика та вправи (Stage Builder + share):**

- організатори та **RO** — схема для майданчика й передача учасникам;
- тренери й клуби — брифінги без окремого CAD;
- стрілки — 3D, відстані, розташування мішеней.

**Портал без відкриття редактора:**

- стрілець — запис на матч, перегляд каталогу, Hit Factor на лінії, правила в **RO Helper**;
- організатор матчу — конструктор події в **модулі «Матчі»**, робота з заявками та експортом **`.psc`**;
- клуб / платформа — модерація організаторів, політики контенту (share).

### A.4. Проблема → рішення (не лише «план вправ»)

Окрім задач із **§A.2**, портал адресує **інші побутові потреби** на тій самій автентифікації та бренді.

| Проблема / потреба | Як допомагає Shooters Tools |
|--------------------|-----------------------------|
| **Зібрати змагання** без розкиданих чатів і табличок «на око» | Модуль **«Матчі»**: місця, заявки, ростер, прив’язка вправ з **share**, вигрузка в **PSC** |
| **Швидка довідка** на секторі або в паузах | **RO Helper**, **Hit Factor** — без встановлення додатків |
| **Показати вправу учаснику** без «надішли файл» | Посилання **`/v/…`** і QR у PDF редактору |
| **Один вхід** для запису й профільних даних учасника | **Акаунт** (**Supabase Auth**) |
| Спроєктувати план **в метрах** і зняти сумніви по геометрії сцени | **Stage Builder** (сітка, 3D, PDF) |

### A.5. Цінність (узагальнено)

- **Портал як хаб:** усе на **одному домені й одному SPA** — менше перемикань між сайтами.
- **«Від оголошення до мішені»:** каталог матчів → запис → зв’язок з вправою, зібраною в **Stage Builder** → експорт для **MD** в **PSC** (розвиток модуля — у **[MATCH_PORTAL_PRODUCT_PLAN.md](./MATCH_PORTAL_PRODUCT_PLAN.md)**).
- **Редактор залишається сильним ядром** для професійної геометрії майданчика (штрафні, активації, PDF тощо) — див. [FUNCTIONALITY.md](./FUNCTIONALITY.md).

### A.6. Модуль «Матчі» (докладніше)

Публічний **каталог** майбутніх подій, **картка матчу**, **заявка** стрільця, **кабінет організатора** (матч, заявки, ростер, програма вправ через share **`/v/…`**), **експорт `.psc`** (є **перша версія** серверної збірки). Організатори проходять **модерацію** платформи; є **сповіщення про заявки організаторів** — [SUPABASE_ORGANIZER_APPLICATION_ALERTS.md](./SUPABASE_ORGANIZER_APPLICATION_ALERTS.md).

На **production** маршрути з’являються лише за **`VITE_ENABLE_MATCH_PORTAL=1`** — [MATCH_REGISTRATION_AND_PSC_PLAN.md §1.4](./MATCH_REGISTRATION_AND_PSC_PLAN.md). Беклог **MA‑*** — [BACKLOG_MATCHES.md](./BACKLOG_MATCHES.md).

### A.7. Типові сценарії (змішані)

1. **Зайти на сайт під своєю мовою** → головна порталу → обрати **матч**, **довідник** або перейти в **редактор**.
2. **Знайти подію та подати заявку** (за увімкненого модулю матчів) → профіль або гостьовий потік за політикою матчу.
3. **Вести матч як організатор** — створення опублікованої картки, заявки, ростер, оновлення вправ із **share group**, завантаження **`.psc`**.
4. **Спроєктувати вправу** — **`/:locale/stage-builder`**: поле → мішені → 3D / PDF → **«Зберегти»** в акаунт або **Поділитися**.
5. **Продовжити чернетку вправи** в браузері — `localStorage` (окремо від акаунта та файлу на диску).
6. **Оновити PWA** редактора — банер після збірки (див. [FUNCTIONALITY.md](./FUNCTIONALITY.md)).

### A.8. Монетизація та підтримка

Портал позиціонується як **безкоштовний** для кінцевого користувача в поточній моделі. Канали зворотного зв’язку та опційної підтримки — [README.md](../README.md). Ідеї — [USER_FEEDBACK.md](./USER_FEEDBACK.md).

### A.9. Обмеження та застереження

- Частини UI (мінімум пострілів, кути безпеки на плані) — **орієнтовні підказки**, не регламент.
- Файли вправи **`*.stage.json`** між пристроями — **обмін файлом** або **share**; **немає** повної «хмари всіх моїх вправ редактора» як унікального продукту (share — епік **BL-001**).
- **Акаунт Supabase** — для сервісів **порталу** (запис на матчі, профіль тощо) і **не** замінює повноцінне хмарне сховище файлів редактору для всіх даних користувача.

## Частина B. Технічний опис

### B.1. Стек технологій

| Шар | Технології |
|-----|------------|
| UI | React 19, TypeScript |
| Стан редактора | Zustand; undo/redo — `zundo` для **сцени** |
| Збірка | Vite 8, `vite-plugin-pwa` |
| 2D / 3D редактора | Canvas 2D; Three.js, R3F, Drei (lazy) |
| PDF | jsPDF, jspdf-autotable, qrcode; Roboto для кирилиці |
| Markdown (картка матчу тощо) | `react-markdown`, **`remark-gfm`** |
| Бек і дані | **Supabase** (Postgres, RLS, Auth, RPC); **Vercel** Serverless / Edge (**middleware**, **`/api/*`**) |
| Тести / якість | Vitest; ESLint; **`npm run check`** як у CI |
| Деплой | GitHub Actions, **`main`** / **`staging`** → Vercel |

### B.2. Архітектура застосунку (SPA)

Один **`BrowserRouter`** у **`main.tsx`** обслуговує:

- **`/:locale/**`** під **PortalShell** — home, утиліти, акаунт, **редактор** (**`/:locale/stage-builder`**), **lazy**-маршрути **RO Helper**; опційно **«Матчі»** (**`isMatchPortalEnabled()`**);
- **`/stage-builder`** — редірект на локалізований шлях редактора;
- **`/v/:id`**, **`/e/:id`** — завантаження share з Supabase (**див. TECH**).

**Serverless артефакти** збірки: **`api/publish-share.js`**, **`api/match-export-psc.js`** (CommonJS узгоджено з **`package.json`** у **`api/`**).

### B.3. Каталоги `src/` (зведено)

Зверху вниз: **спочатку портал і сервер**, потім **ядро редактора**.

| Шар | Шлях | Роль |
|-----|------|------|
| **Портал** | `src/portal/` | Shell, matches, Hit Factor-маршрути, RO lazy, акаунт; **`POST /api/match-export-psc`** з **`src/server/`** |
| **Контент RO Helper** | `src/ro-helper/` | Markdown, glob ФПСУ/IPSC тощо |
| **Сервер / SEO** | `src/server/`, `src/seo/`, `src/lib/` | Handlers PSC і publish-share, канонічний origin |
| **Domain** | `src/domain/` | Редактор: мішені, геометрія, `*.stage.json` |
| **Application** | `src/application/` | `stageStore`, `briefingStore`, чернетка |
| **Presentation** | `src/presentation/` | Canvas 3D, PDF, UI редактора |
| **i18n** | `src/i18n/` | Усі тексти SPA (укр./англ.) |

### B.4. Дані й формати

- **`*.stage.json`** + версія **`STAGE_PROJECT_VERSION`** — [TECH.md](./TECH.md).
- **Чернетка** редактора — `localStorage` (debounce).
- **Share** — рядки та payload у Postgres (**RLS**) — **BL-001**.
- **Матчі** — таблиці `matches`, реєстрації, скводи, лінки вправ (**SUPABASE_MATCH_ADMIN**).

### B.5. Підсистеми (продуктово-технічно)

| Підсистема | Призначення |
|------------|-------------|
| **Портал** | Навігація UK/EN, акаунт, SEO **Helmet** на локалізованих сторінках |
| **Матчі + API** | UI у `portal/matches/*`; серверна збірка **`.psc`** |
| **2D-план редактору** | Сітка, вимір, активації, undo сцени — [FUNCTIONALITY.md](./FUNCTIONALITY.md) |
| **PDF / PWA редактору** | Брифінг A4 + знімок; офлайн після першого візиту |
| **Share + Edge OG** | `middleware`, боти, попередній перегляд посилання |

### B.6. Якість, CI та середовища

- **CI** — `npm run check` на `main` та `staging`.
- **Staging** — Vercel **`stage-builder-staging`** ([stage-builder-staging.vercel.app](https://stage-builder-staging.vercel.app)), **`VITE_SITE_ENV=staging`**, **`VITE_ENABLE_MATCH_PORTAL=1`** — [TECH.md](./TECH.md).

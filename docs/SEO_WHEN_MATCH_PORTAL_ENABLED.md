# SEO і видимість: коли матч-портал увімкнено в проді

Окрема задача після **`VITE_ENABLE_MATCH_PORTAL=1`** (або еквіваленту у вашому деплої) у production.

## Копірайт і мета

- Оновити **`portal.metaDescription`** / **`portal.helmetTitle`** (UK/EN у `src/i18n/messages.ts`), якщо потрібно згадати **опубліковані матчі**, **реєстрацію**, **кабінет організатора** — лише коли функції реально доступні всім користувачам.
- За потреби додати окремі рядки SEO для маршрутів `/:locale/matches` та карток матчів (через `Helmet` на відповідних сторінках або розширення `applySeoMeta` у `I18nProvider.tsx`).
- Переглянути **`index.html`**: за замовчуванням краще залишати опис **порталу цілком**, без обіцянок модулів, які ще приховані прапором.

## Технічне

- **Canonical / hreflang**: якщо з’являються нові значущі URL (наприклад локалізовані сторінки матчів), узгодити з тим, що генерує білд (`__SITE_ORIGIN__` тощо).
- **Sitemap** (якщо використовується): додати публічні маршрути матчів, коли вони стабільні.
- **Open Graph**: при потребі окремі `og:title` / опис для хабу матчів і сторінки матчу; після зміни `public/og-image.png` збільшити query у `src/seo/ogConstants.ts` і задеплоїти.
- **Google Search Console**: перезняти індексацію ключових URL після релізу; перевірити, що TXT-верифікація домену не зламалася.

## Перевірка перед релізом прапора

- Сторінка порталу без зайвих «coming soon» для матчів, якщо вже у проді.
- У коді немає суперечливих env (staging vs prod) для API матчів.
- Швидкий прохід: `/uk`, `/en`, `/stage-builder`, `/uk/matches` (якщо увімкнено), публічна картка матчу.

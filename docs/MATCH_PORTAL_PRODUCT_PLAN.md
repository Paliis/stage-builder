# План розвитку модуля матчів — зведення (2026-05)

**Призначення:** зафіксувати **узгоджений напрямок** після останніх обговорень (тип події, рівні PractiScore, публічна картка), **пронумеровані кроки** наперед і зв’язок із **[беклогом](./BACKLOG.md)** (`BL-NNN`). Деталі фаз A–F, модель даних і PSC — у **[MATCH_REGISTRATION_AND_PSC_PLAN.md](./MATCH_REGISTRATION_AND_PSC_PLAN.md)**; схема Supabase — **[SUPABASE_MATCH_ADMIN.md](./SUPABASE_MATCH_ADMIN.md)**.

---

## 1. Що вже зроблено (остання серія робіт)

Кроки нижче — **історичні**, для орієнтації; у беклозі не дублюються як окремі `BL` (це інкремент до епіку **BL-025** / експорту **BL-028**).

| № | Результат |
|---|-----------|
| **1** | Колонки **`matches.match_event_kind`** (`training` \| `match` \| `classification`, nullable) та **`matches.ps_match_level`** (`L1`…`L5`, nullable); міграція **`20260511100000_match_event_kind_ps_match_level.sql`**. |
| **2** | Форма організатора: вибір типу події та рівня PS; валідація та доменні константи (**`src/domain/matchTaxonomy.ts`**). |
| **3** | Експорт **`.psc`**: у `match_def.json` поле **`match_level`** тільки для валідних **L1–L5**; якщо порожньо — ключ не додається (**PractiScore-узгоджено**). |
| **4** | Публічна картка матчу: завжди видимі рядки **«Тип події»** та **«Рівень (PractiScore)»**; для незаповнених полів — текст **«не вказано»** / **«Not specified»** (i18n). |
| **5** | Міграція застосована до зв’язаного Supabase (**`db push`**). |

| **2** | **Seed для демо** | Оновити **`supabase/seed/`** для тестового матчу: заповнити **`match_event_kind`** та **`ps_match_level`**, щоб демо та скріншоти не показували лише «не вказано». | **BL-034** |
| **3** | **Каталог публічних матчів** | На **`/{locale}/matches`** (список опублікованих): показати тип події та/або рівень у картці рядка; опційно — фільтри за **`match_event_kind`** / **`ps_match_level`** (потрібні індекси або обмежений запит — оцінити перед імплементацією). | **BL-033** |
| **4** | **Список «Мої матчі»** | За потреби узгодити з п. 3: компактні колонки або бейджі типу/рівня для швидкого сканування організатором. | *поки без окремого BL — уточнити після п. 3* |
| **5** | **Епік реєстрації та PSC (і далі по фазах)** | Продовжувати **[MATCH_REGISTRATION_AND_PSC_PLAN.md](./MATCH_REGISTRATION_AND_PSC_PLAN.md)**: підтвердження заявок (**фаза B**), стабілізація прив’язки вправ і експорту (**C–D**), зборний PDF (**E**) тощо. ## 3. Беклог — нові пункти під цей план

Скрізні ID та повна таблиця — у **[BACKLOG.md](./BACKLOG.md)** (розділ «Матчі…»). Коротко:

| ID | Тема |
|----|------|
| **BL-033** | Публічний список матчів: відображення та/або фільтри за типом події й рівнем PS. |
| **BL-034** | Оновлення seed: тестовий матч із заповненими типом і рівнем. |
| **BL-035** | Документація / підказки для організатора щодо типу події та рівня PS. |

**Наступний вільний номер після цих:** див. останній рядок блоку беклогу в `BACKLOG.md`.
